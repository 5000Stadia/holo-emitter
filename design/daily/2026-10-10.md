## R65 so far: what changed and what it bought

Each change below was checked for identical output: the built houses (the manor, the case, the banqueting house and Alice's hall) have vertex digests that match the ones before.

- **A returning player no longer switches to the slower renderer** when the first one kept up with the screen. That trial had cost 2–8 s on a second visit.
- **The anti-flicker pass is faster.** It now pairs each triangle only with its neighbours, and skips faces that merely touch. On the same 40 test planes it finds the same pairs. It used to make 11 M pair comparisons per manor load.
- **The copies of furniture built only to be measured** skip the anti-flicker pass. A one-millimetre lift inside a thing can't change its size.
- **A suspect's face for the panel is painted when you first open their panel**, not at load.
- **Result:** the case's house build went from about 5.4 s to about 4.65 s, on desktop under headless Chromium.

**Measured and dropped.** The audit thought the ~100 code files cost about 3 s on a phone network. Tested over HTTP/2, the way GitHub Pages serves them, listing every file up front saved nothing measurable. On a phone network the time goes to three.js's own download, then the build.

**What's left between us and "half the time":**

- The real gains are:
  - building the room you start in first and the rest after you're walking;
  - keeping the built house between visits.
