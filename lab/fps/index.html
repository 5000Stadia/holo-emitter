The fps lab ledger

The same scene, built from one spec and one layout (same objects, same polygons, same camera path), changing one thing at a time. Measured on this machine's GPU in headless Chrome. Each cell is frames per second; under it, the milliseconds that change adds to the base frame (negative means it saves time). Green marks the fastest engine for a fair case. Cases marked in red were not drawn the same in both engines, so their number is not a comparison.

What it says so far

  • How we build beats which engine. Drawing 1,000 spheres as one instanced batch instead of 1,000 meshes is about 10× faster in every engine. 10,000 separate meshes run at 11–24 fps; instanced, 230–340.
  • Godot has less overhead per object (217 fps against 135–149 for 1,000 separate meshes), and cheaper shadows in its web renderer.
  • three.js is faster on raw geometry and instancing (23M triangles at 66 fps against 44), and Rapier's physics step is faster than Godot's (3.1 ms against 4.7 ms for 500 boxes; 6.5 against 8.2 for 2,000).
  • Godot's web export uses its Compatibility renderer. Here it drew no ambient occlusion, no visible point lights, and no clearcoat. Its high-quality Forward+ renderer does not run in a browser.
  • Download: Godot's web engine is a 39.5 MB WebAssembly file before any content. three.js's WebGPU build is 0.8 MB (about 0.23 MB gzipped).
